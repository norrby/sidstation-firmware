# Why R33 and not R34

Elektron's last SidStation OS is 1.11 R34. This patch is built on 1.10 R33 because R34 breaks the
SidStation's own SysEx editing. This is the result of reading both OS images side by side; R34 has not
been run on hardware for it.

R34 is R33 rebuilt: most code sits 6–20 bytes higher up to $B7FF, and the sound engine
($8A00–$9A00) is the same code, only moved. The SysEx header, ids 01–04, the reception of 02 patch
frames and the dumps are unchanged.

## What changed

- **The direct-parameter receiver (id 04) is broken.** R34 swaps the two address bytes
  (address = edit buffer + `b2 << 7 | b1`) and no longer shifts the mask
  (`mem = (mem & ~mask) | ((value << shift) & mask)`). A parameter frame in the format of the manual
  and of R33 therefore writes somewhere outside the edit buffer, often into the patch memory.
  An editor that changes parameters live does not work, and can damage stored patches.
- **The patch memory is erased** at the first start after the upgrade (a marker word $BABE at $7FE7).
- **Program change 100–127** is not range checked (likely a bug).
- A few small fixes in the display and table code, and a flash routine of its own, with different
  LED behaviour.

## Conclusion

Stay on R33. The patch's hooks could be moved to R34 ($808E, $82C3, $A1F7; free space $B0F9–$B7FF),
but that would inherit the broken parameter receiver.
